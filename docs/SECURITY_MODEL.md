# nestlink 13.0.0 的权限与连接

所有客户端必须登录自建 HTTPS 服务。账号密码、短期访问令牌、自动续期和可撤销设备凭据组成认证流程。MFA、恢复码和设备接入码的旧逻辑已移除；事务迁移清除旧秘密并使旧管理会话失效，同时保留有效后台设备凭据、设备身份和穿透配置。

同账号目录只返回自己的有效设备；跨账号按设备 ID 请求协助仍须被控端批准或验证密码。服务端签发短期远控许可，原生核心在发起、接受连接时验证。退出或撤销前台会话立即结束相关远控；后台设备凭据和租约独立管理，撤销该设备停止其服务。

hbbs 公钥作为原生客户端的信任锚，控制中心不挂载私钥卷。Windows 使用 DPAPI，Linux 使用 Secret Service，Android 使用非导出 AES-GCM Keystore 密钥。平台存储拒绝损坏和篡改，导航 URL 不含凭据，深链接与系统入口统一检查登录。

原生远控只允许认证加密的直连；浏览器画面与输入经直接 WebRTC 数据通道传输，验证 DTLS 和非中继候选。Server 只提供认证、许可与信令，不转发画面；直连失败明确结束。内置远控没有 hbbr、TURN 或 FRP 回退。

内网穿透保留权限、端口池、ACL、HTTP 访问保护、限速与额度。FRP 服务数据经过服务器，不能将其作为内置远控的回退通道。TCP/UDP 目标服务自己负责应用认证。

Sigstore 证明 GitHub 发布工作流身份、源码与真实附件摘要。Windows 没有 Authenticode 发布者签名；Android 保留原证书。签名与实际验收分别核验，范围见 [发行说明](HOMEDESK_RELEASE.md)。
