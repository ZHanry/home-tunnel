Product boundary

Built for home services, not arbitrary proxying.

Home Tunnel centralizes identity, policy, traffic, and audit while restricting clients to configurations issued by the control center.

Good fit

  • Remote NAS and photo access
  • Home Assistant
  • Short-lived development previews
  • User, device, and bandwidth policy

Not a fit

  • Anonymous public proxy services
  • Arbitrary FRP commands or UDP forwarding
  • Unauthenticated sensitive dashboards
  • A public dynamic demonstration server

Default boundaries

  • Short-lived leases and immediate revocation
  • Capability-restricted FRP Agent
  • Separated control and application traffic
  • Connection, traffic, and action audit

Quick Start

Run your own Home Tunnel in three steps.

You need a public Linux server, a domain, and a Linux client that can reach the home service. Read the full guide and replace every example value.

1

Prepare DNS and firewall

Point console and tunnel names at the server. Open TCP 80, 443, and 7000.

2

Generate and start

Use the repository script to create local secrets and Compose configuration, then start four services.

3

Enroll and publish

Change the bootstrap password, create a user, and enroll a home Linux device.

git clone https://github.com/ZHanry/home-tunnel.git
cd home-tunnel
./deploy/scripts/new-selfhost-config.sh \
  tunnel.example.com frps.example.com \
  console.example.com admin@example.com
docker compose up -d
docker compose ps

FAQ

Questions to answer before deployment.

How is this different from raw FRP?

Home Tunnel adds users, devices, connections, short-lived leases, access policy, rate limits, traffic sampling, and audit—and restricts the Agent to issued configurations.

Can I expose the real management console as a demo?

That is intentionally discouraged. Pages contains screenshots produced from local fixtures and never connects to a real deployment.

Why does the Windows EXE show an unknown publisher?

The Experimental EXE uses an ephemeral self-signed certificate. Verify its Release SHA-256 and Sigstore evidence; a trusted publisher prompt still requires a public Authenticode certificate and protected signing environment.

Does this site collect deployment addresses or credentials?

No. Pages receives aggregate visits and named click events only. Deployment feedback explicitly forbids domains, IPs, tokens, and credentials.
