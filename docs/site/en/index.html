Candidate downloadsScope and verification

Direct P2P

Peers carry the remote session.

The native Rust/Flutter core requires an authenticated, encrypted direct connection. hbbs provides only ID and NAT signaling. No hbbr, TURN, FRP, HTTP/WSS, VPN or vendor fallback; failed direct connections terminate.

The Web console opens the installed HomeDesk client through an ID-only homedesk URL. The account directory cannot bypass a remote password or approval; recent registration is not proof of live media.

Choose when to share your screen.

Configure your own HTTPS console, hbbs address and public key. Generic packages contain no server, key or account. Android screen sharing requires current system permission, including a visible-app authorization on Android 14/15.

FRP 0.70.1

Keep local services online.

HTTP/HTTPS and governed TCP/UDP, port pools, access control, traffic quotas, diagnostics and independent CLI/NAS/background Agents remain available. Remote mode changes or a failed remote session do not stop independent tunnels.

Server retains Node/SQLite and the existing Caddy, traffic-gateway and FRPS stack. The only new resident process is hbbs, capped at 64 MB. Native macOS/Linux GUIs are not released; the CLI bundle covers five platforms.

Before installing

Can remote control use a relay?

No. HomeDesk 11 requires authenticated encrypted direct P2P. Failed NAT traversal stops the session.

Are existing tunnels retained?

Yes. Independent HTTP/HTTPS and governed TCP/UDP, permissions, port pools, ACLs and traffic management remain.

What does the candidate verification cover?

Build, source, unit, widget, installer and emulator checks have separate scopes. Sustained two-peer media, cross-network NAT and physical Android devices remain pending. Historical 10.0.0 and 9.0.0 evidence is not 11.x acceptance.

What needs a backup?

SQLite, deployment secrets, client state and the separate hbbs identity. Retire legacy remote overlays before migrating.
