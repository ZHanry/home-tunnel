Product boundary

Built for home services, not arbitrary proxying.

Home Tunnel centralizes identity, configuration, and audit; the Web path adds access and traffic policy. Client capabilities stay restricted to configurations issued by the control center.

Good fit

  • Remote NAS and photo access
  • Home Assistant
  • RTSP-over-TCP and fixed-port UDP
  • User, device, and bandwidth policy

Not a fit

  • Anonymous public proxy services
  • Raw IP, ICMP, broadcast, or multicast
  • Unauthenticated sensitive dashboards
  • STCP, XTCP, SUDP, visitors, or arbitrary plugins

Default boundaries

  • Short-lived leases and immediate revocation
  • Capability-restricted FRP Agent
  • Separated control and application traffic
  • Connection configuration and action audit

Dependencies and code

Each code repository runs CI, dependency checks, CodeQL and secret scanning. Test packages retain checksum and signing verification.

Raw-port boundary

TCP/UDP are off by default and bypass Caddy/the gateway. Applications must authenticate and encrypt; firewall source/rate limits are essential for UDP amplification risk.

FAQ

Questions to answer before deployment.

How is this different from raw FRP?

Home Tunnel adds users, devices, connections, short-lived leases, access policy, rate limits, traffic sampling, and audit—and restricts the Agent to issued configurations.

How do I tunnel RTSP or RTP/RTCP?

RTSP is not a separate type. Map public TCP 10554 to camera port 554 and use ffplay -rtsp_transport tcp rtsp://PUBLIC_HOST:10554/path. Native RTP/RTCP over UDP needs fixed media ports and one mapping per port; dynamic ports are not guaranteed.

Can I expose the real management console as a demo?

That is intentionally discouraged. Pages contains screenshots produced from local fixtures and never connects to a real deployment.

How do I install the Windows client?

Build a complete test package from the client repository. The package includes the GUI and managed Agent. Source builds are the primary path during internal testing.

Does this site collect deployment addresses or credentials?

No. Pages receives aggregate visits and named click events only. Deployment feedback explicitly forbids domains, IPs, tokens, and credentials.
