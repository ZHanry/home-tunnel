Home Tunnel 8.0.0

8.0.0 保留隧道与设备管理，增加独立授权的远程桌面。正式版本号不代表完整方案或全部平台已验收。请根据下面的实现范围选择环境，并核对各组件 Release 中的实际产物与最终安装包证据。

当前远控范围

  • Windows x64 与浏览器：H.264/VP8 视频、键鼠、中文文本和双向多文件；配对、本机批准和逐项权限控制。最终 Windows 包的同机验证已覆盖真实视频、输入和文件；完整文件选择、多屏、高 DPI、锁屏与跨网仍待验收。编码证据来自软件路径，不代表硬件加速已验证。
  • Linux x64 X11：仅观看、键盘和鼠标。当前证据来自隔离 Xvfb 环境，实体桌面和锁屏恢复未验收；文本、剪贴板和文件不可用。Linux arm64、NAS 和 CLI 继续提供隧道功能。
  • Android：保留多服务器管理，接入同源核心、JNI 与 Surface；真机解码和输入未验收。音频、麦克风回传、剪贴板/文件、多会话界面与增强编码不可用。

远控画面、输入和文件只能走两端 UDP P2P。服务器负责身份、授权、信令和 STUN；无法直连时明确失败，不回退至 TURN、FRP、HTTP 或 WSS 载荷转发。原有隧道业务仍使用自己的公网服务端转发。

尚未交付或完成验收

macOS/Wayland 被控、桌面原生观看窗口、系统声音、麦克风回传、虚拟麦克风与 AV1/HEVC 尚未交付。Windows 文本剪贴板已有实现，实际系统互通未验证。多窗口媒体并发、真实跨网、完整升级恢复、8×5 平台组合以及 2 小时活动/24 小时在线验收仍未完成。

Android 被控、登录前/UAC 安全桌面、跨账号共享、图片剪贴板和目录递归传输不在当前范围内。未支持的能力在界面中保持不可用；模拟器、隔离环境与云端构建均不能替代对应实机证据。

Windows/macOS 平台签名状态以每个实际产物报告为准。Android 沿用原 applicationId 和发行证书。网站控制台图片仍是标明版本的 7.0.0 历史示例。

8.0.0 scope and limits

Windows-to-browser H.264/VP8 video, keyboard/pointer, Unicode text and bidirectional files have passed same-machine checks of the final Windows package. Final-package results belong to the separate Release evidence. Full file-picker interaction, multiple displays, high DPI, lock/unlock and cross-network use remain unverified; current codec evidence uses software encoding.

Linux x64 X11 exposes viewing, keyboard and pointer only. Its evidence comes from isolated Xvfb tests; physical desktops and lock/unlock remain unverified. Text, clipboard and files are unavailable. Android integrates the shared controller, JNI and Surface, but physical-device decoding and input remain unverified. Android audio, microphone return, clipboard/files, multi-session UI and optional codecs are unavailable.

macOS/Wayland hosting, native desktop viewers, system audio, microphone return, virtual microphones and AV1/HEVC are not delivered. Windows system clipboard, concurrent media windows, cross-network traversal, complete upgrade/restore and long-running acceptance remain outstanding. The version number does not imply that the complete plan has passed.

Remote-desktop payloads require direct UDP P2P. The server handles identity, authorization, signaling and STUN; an unavailable direct path fails with no TURN, tunnel, HTTP or WSS payload fallback. Existing tunnel services retain their server-forwarded path.
