# 升级到 nestlink 13.0.0

发行组合为 Server、Client、Android 和内部 Agent 13.0.0，FRP 0.70.1。保留旧标签和原发行字节；当前网站使用 13.0 的界面和下载。生产服务升级需单独安排。

1. 保存旧安装包与配置，备份 SQLite、部署 secrets、客户端状态和 hbbs 身份卷。数据库迁移后回退需要恢复对应旧备份。
2. 核对 SHA256SUMS 后升级 Server。事务迁移清除 MFA、恢复码和接入码秘密，使旧管理会话失效；保留有效后台设备凭据、设备身份、穿透配置、权限、端口池、ACL 和流量治理。按 [自建说明](SELF_HOSTING.md) 配置信令地址、公钥和 HTTPS。
3. 停止历史远控组件及 `compose.rd.yaml` / `compose.turn.yaml` 覆盖。旧远控媒体会话不延续到新核心。独立运行的历史后台穿透可保留其有效凭据；13.0 不再提供独立 CLI/NAS 发行。
4. Windows x64、Linux x64/ARM64 安装对应 GUI，重新登录自建 HTTPS 服务，配置自动获取。Android 安装通用 APK；applicationId、原发行证书和升级身份不变，versionCode 为 13000000。新远控身份登录后登记。
5. 在桌面工作台检查设备、穿透配置和后台状态，验证 HTTP/HTTPS、受控 TCP/UDP、权限、ACL、额度和诊断。Web 直接在浏览器内远控；原生与浏览器均须被控端批准或验证密码，直连失败结束。

桌面主窗口固定 1120×760，按屏幕/DPI 缩小，禁止自由缩放和最大化；远控窗口保留全屏。关闭远控不停止独立后台穿透，撤销后台设备停止对应服务。

Windows 未配置 Authenticode 发布者签名。Android 保留系统授权边界；手机产品提供管理和远控，不新增手机被控发行承诺。实际验证与尚缺的真机、运营商网络、长期媒体等范围见 [发行说明](HOMEDESK_RELEASE.md)。

回退前停止新组件，恢复旧 SQLite、部署秘密和 hbbs 身份，再使用对应旧发行字节。两版本不同时读写同一个 SQLite 文件。
