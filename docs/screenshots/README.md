# Current NestLink captures

14.0.0 capture tools require an exact selected source and product version. Pending pages may keep accurately labeled 13.0.0 stable images; the promoted 14.0.0 site must use genuine 14.0.0 captures. Product screenshots preserve original pixels and record the source commit, browser or installed package, dimensions and SHA-256. Component previews use a separate capture kind and say example data in both languages; they do not establish installed-app or remote-session acceptance.

`capture-product.mjs` uses the unchanged current Server UI and its isolated preview data. It checks the exact source commit and collects the three current navigation views, light/dark device management, available device details, account/settings, secondary administrator views and the first three tunnel wizard steps. It uses the preview's real login path and does not intercept API responses, rewrite the UI, start a remote session or submit a service. The Product screenshot capture workflow stores originals and their manifest for review.

The local preview command is `node docs/screenshots/capture-product.mjs SERVER_CHECKOUT STAGING_OUTPUT`, with `CAPTURE_SOURCE_SHA` and `CAPTURE_PRODUCT_VERSION` set to the exact selected source/version. This preview output has `installed_application: false` and `synthetic_data: true`.

Before every screenshot, both capture paths wait for fonts, two animation frames, all finite CSS transitions/animations to finish, and two final drawing frames; the screenshot API also disables animations. Theme switching therefore captures settled pixels. In addition to desktop views, the scripts capture the three primary views in light and dark at 390 × 844 and 320 × 720, each at the page top and after actual scrolling to the bottom. These are viewport screenshots (`full_page: false`) so fixed bottom navigation is preserved. Each original records viewport, scroll position, document size, horizontal overflow and navigation bounds; an unscrollable page can honestly have the same top and bottom scroll position. No product styles are injected or altered to obtain a screenshot.

For the actual isolated installed server, run `node scripts/capture-nestlink-web.cjs` with `NESTLINK_CAPTURE_ORIGIN`, `NESTLINK_CAPTURE_SOURCE_SHA`, `NESTLINK_CAPTURE_VERSION`, `NESTLINK_CAPTURE_SERVER`, `NESTLINK_CAPTURE_OUTPUT`, `NESTLINK_CAPTURE_CREDENTIALS_FILE` and `NESTLINK_CAPTURE_ISOLATED_FIXTURE=true`. The credentials JSON is private, outside the repository, and supplies an `admin` object containing `username` and `password`; an `accounts.admin` object or an `accounts` array with an administrator role also works. Neither values nor browser call logs are printed. The origin must be a private fixture address. Before login and capture, every served tracked HTML/JS/CSS/SVG asset is compared against the selected Git blob bytes, avoiding checkout line-ending differences. This output records `installed_application: true` and exact served static-asset hashes. Both paths share `scripts/capture-nestlink-views.cjs` and keep UI-only scope explicit.

For installed desktop and Android captures, use the accepted installer/APK bytes and record their hashes. Review every original image before adding it to `docs/site/screenshot-slots.json`, then run the site policy checker. Keep old captures in historical Git history, not on current pages or in current assets.
