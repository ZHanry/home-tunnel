# 8.0 正式版发布要求

维护者已决定直接发布 `8.0.0 / v8.0.0` 正式版，并在发布完成后仅保留四仓的 `main` 分支。历史候选工作记录保留，但不再作为必须先发布 RC 的要求。稳定下载入口现已绑定公开的 8.0.0 组件产物与独立核验后的摘要，7.0 历史下载保留。

发布过程验证实际 Windows 安装包中的 UDP 视频、输入与文件传输、自动化安全检查及发行产物身份。实际不支持的系统、声音、虚拟麦克风和增强编码能力须保持不可用；缺少的实机、跨网、升级恢复、签名和长期验收逐项写入 Release 限制，不能将正式版本号当作这些验收已通过的证据。

正式清单更新 `releases.json`、网站副本及 `VERSION`，绑定四仓实际 Release 标签、提交、附件、SHA256 和测试报告。尚未生成真实产物时不预填摘要。7.0 历史下载保留。API 使用独立正式标签 `api-v1.2.0`；API 契约提交与服务端发行提交分别核对。

```powershell
python scripts/check-release-entry.py
python scripts/verify-stable-release.py
```

第一条检查入口清单结构，第二条实际访问四仓 GitHub Release，确认公开正式版、标签提交和附件，并重新下载清单列出的产物计算摘要。不能用本地结构检查替代真实下载验收。

交付顺序：冻结正式契约 → 桌面核心/客户端 → Android 同源核心及原发行证书 → 服务端真实客户端基线/镜像 → 入口清单。Android 8.0.0 使用 `versionCode 8000002`，保留原 applicationId 与发行证书。客户端发布分为标签构建和原始安装包验收后发布两个步骤；最终原始字节的证据不能由开发构建报告替代。失败检查需修复并保留记录。完成后清理已合并开发分支，保留历史标签。
