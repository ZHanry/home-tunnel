# Launch 2026-08 owner runbook

This document prepares the 30-day validation campaign without publishing any external post or third-party pull request. Every external submission requires the repository owner's final review and confirmation immediately before submission.

> **Status (2026-08-13):** Pages enablement, repository/profile changes, Releases, campaign posts, third-party pull requests, analytics setup, and campaign measurements are not completed by this local audit. They remain owner-only actions.

## Goal and definitions

- 200 unique GitHub Pages visitors in 30 days.
- 20 repository Stars in 30 days.
- 10 valid deployment results from non-maintainers.
- A valid result contains a real platform, installation outcome, and blocker or success note. It never requires a domain, IP address, credential, token, certificate, or private log.
- Treat GitHub clones as directional only. CI checkout activity can contaminate clone counts and must not be reported as user growth.

Campaign parameters for every external link:

```text
utm_source=<channel>
utm_medium=<post|profile|listing|social>
utm_campaign=launch_2026_08
```

## Analytics setup

1. The owner manually creates a GoatCounter site; automated account registration is not allowed.
2. Set repository Actions variable `GOATCOUNTER_ENDPOINT` to the public HTTPS endpoint ending in `/count`.
3. Pages loads analytics only on `zhanry.github.io`; an empty variable disables analytics.
4. Named events are `quick-start*`, `release*`, `github*`, and `deployment-feedback*`.
5. Keep GoatCounter's default aggregate pageview measurement enabled so unique-visitor goals remain measurable. Do not enable enhanced visitor identifiers or add deployment identifiers or user data to event names.
6. Save GoatCounter and GitHub Traffic snapshots at D0, D7, D14, and D30 under the campaign archive outside the public repository if they contain sensitive referrer detail.
